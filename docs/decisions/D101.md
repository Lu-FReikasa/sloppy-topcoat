# D101 — Research is run by three frames, not by the limits of a server check

> **Status (2026-11-25):** Amended. Profiles per application are built in part ([D116](D116.md); research profiles since 2026-11-20).

**Decision.** **A run of the Research program has no fixed count or time limit. It has a frame (`quick`, `default`, `thorough`) that decides the shape of the result and when it is finished, and a progress guard that ends a run which stands still.** The asker chooses the frame in the request (`depth`; `standard` and free text read as `default`), a Research chat takes it from its effort stage (Schnell, Normal, Gründlich). The frame is written as a `depth:` line into the header of the request prompt, so a task that is started again after a restart reads the same one (`research_profile.py`). Quality has priority over speed: a thorough run may take hours, a default run as long as its question needs.

- **Frames.** `quick`: an overview of points with sources, a soft time frame (live setting, 15 minutes). `default`: a structured answer, primary sources, at least two hosts for a fact, versions named. `thorough`: a documentation in the manner of a scientific paper (abstract, scope, how it was searched, findings, disagreement between sources, limits, list of sources), as long as the topic needs.
- **No fixed limits.** Turns, tool calls, web searches, web pages, time: all unlimited in `default` and `thorough`. Each can be limited again by a live setting of the group *Research* (`research_max_turns`, `research_max_tool_calls`, `research_time_budget_seconds`, 0 = none), so a limit can be added later without a change of code. The web budget no longer stops at the first usable page.
- **Progress guard.** A run ends (`stop_reason` `no_progress`, the agent is asked to write what it has) when `research_stall_turns` model turns in a row bring no new evidence. 0 switches it off. Repeated identical calls are still stopped as before.
- **Its own prompt.** The agent's system prompt says "diagnosis agent of a home-lab operator", "at most 3 searches and 2 pages" and "at most 4 findings" for every program. For Research those three passages are replaced (`research_profile.personalise`); the rest (evidence tags, data fences, honesty about failed calls) stays. The answer message may be a document (summary 60,000 characters, message body 80,000).
- **Own sizes.** One model answer 4096 tokens (+2048 for a native call), 8000 characters of one page, 48,000 characters of context, a slot of 24,576 tokens (all live settings). The node loads the context it needs (`min_context`); **UNVERIFIED on real hardware** (a reload costs 25 to 35 s, a small card may not fit 24k with the larger model).

**Why.** Research ran with the limits of a server check (3 searches, 2 pages, 20 tool calls, 10 minutes, 3500 characters of a page, 1536 tokens per answer) and a prompt for a home-lab diagnosis, so its answers were short. Development and Projects have no internet and depend on Research for frameworks and error profiles.

**Long reports and the choice of the frame (built after the first slice).** A research run has two more tools beside `research.message.send`: `research.report.section {title, markdown}` stores one section as a note of the task (the same title replaces it) and `research.report.show` lists what is written. When the run sends its result, its `summary` is the abstract and the hub puts the sections behind it as Markdown chapters, so a document is not bound by the length of one model answer. The asking agents choose the frame from a rule in the tool description (`research_profile.DEPTH_GUIDE`, in `project.request.send` and in the kind `request` of `dev.message.send`); the answer tools' descriptions are no longer cut at 400 characters (`agent_prompts.description_limit`).

**Not built yet.** A second model's check of a thorough result before it is delivered (the Project's reviewer run and the code's quote check already look at every research result afterwards), and moving all of this into a per-application profile (models, run, prompt, rights) that replaces the global values. The frames are the first slice of that profile.
