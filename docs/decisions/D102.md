# D102 — A thorough research is a report: a versioned document in the Ablage, Markdown as source, HTML as view

**Decision.** **Every thorough research (the Research chat at Gründlich, a request with `depth: thorough`) ends as a report: a document with a fixed form, kept in the Ablage with versions and comments, that the person reads, releases, has revised or passes on.** The source is **Markdown with typed blocks** (tables, `chart` blocks that hold data, notes); the **view and the export are HTML** made from it (a self-contained file with a table of contents, print style and inline SVG charts). The model never writes the markup of the view, and raw HTML from a run is not stored: text from the web is foreign (D82), and a model-written HTML would be a way for it into the interface.

- **Form.** Title page (front matter: title, the question as asked, date, version, status); *Vorwort* (written by the model: what the report is about, what it paid special attention to, what it left out on purpose); a box *Grenzen dieser Recherche* that **the code** adds (pages that could not be read, claims without a literal quote, points of the request not covered, a run that ended because it stood still); table of contents (code); chapters (model, one section per tool call); *Quellenverzeichnis* (code, numbered: URL, host, time of retrieval, the passage literally); appendix *Entstehung* (code, from `agent_tasks` and `job_records`: models with node and time, start and end, steps, searches, pages, sources, hosts, tokens, the frame, the hub build, how many claims have a literal quote). The language is the one of the question.
- **Storage.** Tables `reports` (the document: title, question, status `draft` / `reviewed` / `released`, current version, task, conversation), `report_versions` (immutable, with a parent version, a content hash, the kind of change `agent` / `revision` / `person`, a note, the metadata as JSON) and `report_comments` (version, anchor = a chapter, author, resolved). Versions work like commits: never changed, a revision is a new version whose parent is the one it revised; the diff is computed (`difflib`). Every row carries `user_id`.
- **Release is the person's click.** Only a released version goes into the knowledge base (the private source "Berichte", as "Projekte" and "Akten" do), can be read by Development and Projects (a read-only tool group `reports`) and can become a document in a project's Akte. A report is "foreign" until then (the structural guard of D82 holds).
- **Not in this decision:** server-side PDF (the browser prints the HTML), images from the web (never loaded from the net into a report; a picture would be fetched by the hub, released by the person and shown from the Ablage), editing the text by the person (comments and revision first).

**Why.** Research is what Development and Projects depend on (they have no web), and a clean research should become the base of the local, growing knowledge. A chat answer is neither citable nor revisable.
