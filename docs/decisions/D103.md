# D103 — The fix of an issue is confirmed as one set, with its whole change shown

> **Status (2026-11-25):** Amended. A fix may also change `web/src/` since 2026-11-20 (the workshop runs lint, typecheck and vitest). The original D103 of 2026-11-04 (one application profile) was overwritten by this text and is restored as [D116](D116.md). On the branch of a large task with an active workshop scope, [D110](D110.md) replaces the click per fix.

**Decision.** **A fix that a run of `issue_fix` wrote (exact edits and new files) is applied in the workshop on ONE click of the signed-in admin, for the whole set, after the page showed every change as a diff. The same click starts the tests.** It amends D99 for this one kind of change: D99 confirms each file change of an assistant on its own.

**Why.** The maintainer wants problems from the running system to go from a short report to a tested fix with as few steps as possible (2026-11-17). A fix is one change that only makes sense whole: confirming its five edits one by one adds four clicks and the chance to apply half of it. D99 left batch confirmation open on purpose; an issue fix is the case it waited for.

**How it is built.** `issue_fixes.py`. The draft is a row of `issue_fixes` with a content hash of its edits; the click (`POST /api/project/fixes/{id}/apply`) is refused for an API key and for anyone but an admin, and when the hash does not match. The steps run in the workshop of the dev node: `repo.start` on `topcoat/issue-<number>`, each edit through `execute_confirmed` (audited as a confirmed change with the fix's id and hash), `repo.diff`, `repo.commit`, `repo.test_start` on a copy of the worktree, and `repo.start live` at once, so other runs read the live code again while the tests run. A red test or an edit whose old text does not occur ends the fix as failed and starts the next `issue_fix` iteration with what went wrong as its feedback (at most two in a row without the person).

**Consequences.** The assistant still never changes a file on its own: it writes the draft, the person applies it. A fix touches only `hub/`, `proto/` and `docs/`. One fix is applied at a time (the workshop has one scratch copy per repository).
