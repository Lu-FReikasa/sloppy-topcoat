# D104 — A tested fix reaches the hub through a spool on the hub host, not through the hub

> **Status (2026-11-25):** Amended. Fixes of `web/src/` are rolled out as well; the host builds the GUI. The original D104 of 2026-11-04 (pools, programs, block programs) was overwritten by this text and is restored as [D115](D115.md).

**Decision.** **A fix whose tests passed is rolled out on a second click of the admin: the hub writes the fix's diff, mapped onto its overlay, into a spool directory of the hub host; a fixed script there, started by systemd, checks it, applies it to a copy of the overlay, swaps it in, restarts the hub and goes back by itself when the hub does not answer.** The hub never restarts itself and never runs a command on the host.

**Why.** The overlay deploy (D98) runs from the maintainer's checkout; a fix made in the workshop has to reach the hub without it. The node on the hub host runs without Docker rights and with `NoNewPrivileges` (no sudo), and `hub.update` (NS-01) waits for a script that restarts the hub, which loses its answer. A spool decouples the two: the hub only writes a request and reads an outcome; the host's script outlives the restart.

**How it is built.**
- Hub: `issue_fixes.FixService.rollout` (only a passed fix, only an admin on the GUI). The diff of `repo.diff` is mapped (`hub/src/topcoat_hub` → `topcoat_hub`, `hub/migrations` → `migrations`, `proto` → `proto`); tests and docs are left out; anything else (web/, node/) refuses the roll-out, as does a cut or masked diff. The request is `request/<id>/{manifest.json, fix.patch, READY}`; the outcome `done/<id>.json` is read when the nodes connect again and when the page asks.
- Host: `deploy/fix-overlay/` (`install.sh` once as root). `hub-fix-overlay.sh` checks every path of the patch, that the overlay runs the commit the fix was made on, and `git apply --check`; dumps the database when migrations change; recreates the hub with the build `<commit>-overlay+fix-<number>`; waits for health; else puts the overlay before back.
- The maintainer's checkout: `deploy-overlay.sh` refuses to push over fixes it does not have; `scripts/dev/pull-fixes.py` brings them in as commits with the trailer `Topcoat-Fix: <label>`.

**Consequences.** Fixes stack on the overlay until the next deploy from the checkout. Two fixes that change the same lines do not apply on each other: the second is refused and made again. A fix of the web GUI still goes through the checkout.
