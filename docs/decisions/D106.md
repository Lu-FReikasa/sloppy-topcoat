# D106 — A desktop client with free windows; themes decide behaviour as data

**Decision.** Next to the web GUI there is a **desktop client** (Tauri 2, WebView2 on Windows; `desktop/`). It is a thin shell
around the same web GUI: every program can be its **own window**, placed freely on any screen; a **global key** opens the
program selector over everything; a tray icon keeps the client running. A program window shows the web GUI with
`?solo=<key>`: one program, no taskbar, its state kept in the window, so several windows never overwrite the person's
desktop state on the hub. The web GUI stays (laptop, phone, any browser) and is built from the same code.

**Themes decide behaviour, still as data.** Besides colours and CSS a theme may set: how windows behave (`floating`,
`tiling`, `single`), their frame (`native` or drawn by the theme), how menus appear (menu bar, palette, hamburger), whether
the taskbar is shown, how the assistant figure stands. The hub checks these fields like every theme field. A theme brings no
code (D70, `docs/THEMES.md`).

**This replaces** the part of D70 that the desktop is one page with tiled programs and no menu bar: tiling stays as one
behaviour a theme can choose.

**Security.** The client opens no port and keeps no token (the sign-in lives in the web view's cookie store); only its local
selector may call its commands, the hub's pages get no IPC; the hub address must be `https://` (D11).

**Decided with the maintainer on 2026-11-11** (plan `2026-11-11-desktop-plugins-clipper-kontext-plan.md`, E1/E2/E5).
The spike of the same day builds the windows, the key and the tray; it is UNVERIFIED on real hardware until it ran on Windows.
