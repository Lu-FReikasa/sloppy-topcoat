# D110 — A workshop scope per large task replaces the click per fix on its branch

> **Status (2026-11-25):** Decided by the maintainer (plan of 2026-11-24, open decision 2; one card per large task confirmed 2026-11-25). Not built: milestone P2 *Large tasks as projects*. Amends [D103](D103.md) for the branches of large tasks only.

**Decision.** **The person gives a large task ([D109](D109.md)) a *workshop scope* by one click on a card ([D83](D83.md)). Inside it, the hub applies the drafts of its sub-tasks, runs tests and builds, takes screenshots and makes theme and persona drafts on that task's branch without a click per fix. Roll-out stays a click; push and merge stay forbidden.**

- **The card shows the whole scope before the click**, and the hub fixes it, never a model: the action kinds below, one registered repository, **exactly one branch `topcoat/v-<nr>`** (the large task's number), the purpose (the large task's title), **14 days**, revocable at any time. One card per large task; a second large task needs its own card.
- **Covered:** apply a draft of a sub-task (edits and new files) on that branch; commit on that branch; run the workshop's tests, lint, typecheck and builds; take screenshots of the workshop build with fake data; make and change theme and persona drafts ([D128](D128.md)) on that branch; repeat after a technical failure or a correction inside the scope (D83).
- **Not covered:** the roll-out to the live hub ([D104](D104.md)), saving or activating a theme or persona, any other branch or repository, `topcoat/live` and `main`. Push, merge, deploy and delete are never grantable (`project_scope.NEVER`); a mandate of this kind cannot carry the push flag.
- **Checks on every attempt** (never waived by the scope): an active scope for exactly this project, repository and branch; the content hash of the draft; the paths a fix may touch (as in D103); no secret (`releases.mask_secrets`); a clean workshop; the stop after the same failure twice ([D120](D120.md)). Every use is a line of the project's Akte (`mandate.used`).
- **Built as** a mandate action `workshop` (`project_mandates.ACTIONS`), created only by the signed-in admin's click on the GUI (`api/mandates.py`), never by an API key or an agent. The coordinator of issue #32 checks it before each write and stops the large task when it is missing, expired or revoked.

**Amends D103.** On a branch `topcoat/v-<nr>` with an active workshop scope, a sub-task's fix is applied without the click that D103 asks for each fix; its diff stays visible in the large task's view. Outside such a scope, an issue fix on `topcoat/issue-<number>` keeps D103's click.

**Why.** A large task has up to eight sub-tasks, each with several drafts; a click per fix would make the background run wait on the person all the time, which defeats the point of decomposing. The workshop is scratch: nothing on a `topcoat/v-*` branch reaches the hub without the roll-out click, so the risk of applying a draft there is bounded by the branch. One exact branch per card (rather than a pattern for a whole project) keeps the scope as narrow and readable as D108's probe mandate and fits the mandates as they are stored today (maintainer, 2026-11-25).

**Not decided here.** Several repositories in one scope; network access during tests.
