# D117 — House models: each node keeps one model for all text work

> **Status (2026-11-25):** Built on 2026-11-14 (`node_policy.house`, `node_policy.workers`, `ModelResolver.house_default`). Amends [D115](D115.md) and replaces the model part of [D85](D85.md).

**Decision.** An admin gives a node one **house model** (`house`: node → model). The node keeps it loaded and serves every kind of text work with it. When nodes have house models, the model lists of the rows of the table no longer decide: a request goes to the house models of the nodes its row allows, the loaded one first, and nothing is unloaded to make room for another model of the same kind. A node without a house model gets no text work in this mode. Nodes listed in `workers` keep a small model for background work (summaries, notes, titles), which goes there first.

The pool of a node ([D115](D115.md)) still says which other models may be used there; the house model is always allowed. There is **no hub-wide default model to set** (the maintainer, 2026-11-06): work that no row decides takes the house model of the first connected node that is not a worker (workers only when nothing else is up), and without house models the best answering model the pools offer.

**Why.** Three different "first" models on two nodes with one slot each made the nodes swap models all day, and every swap cost a load of 25 to 35 seconds. One model per machine that stays loaded is faster for everyone and easier to reason about. A global default model would have been a ninth place that decides the model, which [D115](D115.md) set out to remove.

**Consequences.** Changing which model does the work means changing the house model, not adding model lists to rows. Different kinds of work on one node share one model and its slots. A check from another model family ([D121](D121.md)) needs a second node with another house model, or it falls back to the author's model.
