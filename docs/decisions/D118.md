# D118 — Each application has a contract

> **Status (2026-11-25):** Built as step 1.9 of the plan of 2026-11-24 (`proto/agents/`, `hub/src/topcoat_hub/agent_contract.py`). The seeded tool ceilings are derived from the contracts (issue #7, `ui/seeds.py`). The texts for the person come in English and German (issue #6): the self-description and the GUI's view speak the person's language (stored on the hub; the GUI passes the language it shows; English by default), the answer to "what can you do?" the language of the question. Not built yet: personas, a block field `contract:`.

**Decision.** Every application that has an agent (assistant, research, dev, admin, project) has one contract file, `proto/agents/<key>.json`, checked against `proto/agents/contract.schema.json`: what the application is for, its typical tasks, the tool groups it may use (each said in a sentence), what it never does and what needs the person's click, the answer forms it writes, whom it gives work to, and its model role. The contract is the source for:

- the agent prompt of the application (its role sentence and its own rules, in place of shared bullets about machines that every application inherited before);
- the responsibility of the application in the message registry ([D81](D81.md));
- the self-description: a short one in front of every chat, and a long one that answers "what can you do?" in words (`about_abilities`), never as function names;
- the GUI's view of what an application may do.

The contract describes; it grants nothing. The tool ceiling ([D69](D69.md), applied by one door, [D116](D116.md)), the person's grants ([D20](D20.md)) and the node whitelist stay the gates, and the built-in ceilings are taken from the contracts' tool lists (`ui/seeds.py`, `builtin_templates`); a test checks that each seeded ceiling is its contract's, never more. The contract describes the ceiling; the gates enforce it.

**Why.** Each pipeline had its own prompt, limits and repair rules, and the prompts of the applications were cut out of one home-lab prompt by string surgery, so every application carried remains of it (the project agent once said it could not create a change set it was made for). The only self-image of the chat model were its tool schemas, so it named raw functions. One contract per application gives one place to read and change what an application is.
