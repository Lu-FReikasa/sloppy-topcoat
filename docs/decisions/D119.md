# D119 — A model's answer has a form the server enforces, and a plan names symbols, not lines

> **Status (2026-11-25):** Built as steps 1.10 and 1.12 of the plan of 2026-11-24 (`output_schemas.py`, `proto/agents/outputs/`, `code_symbols.py`).

**Decision.** (a) **Forms.** Where the hub needs JSON from a model (a plan, an investigation, a verdict, a check, the area of an issue), it sends a JSON schema in `response_format`; `llama-server` turns it into a grammar, so the answer cannot leave the form. The schemas live in `proto/agents/outputs/<name>.schema.json`; a block of a block program names one with its field `schema`. The tolerant reader (`json_repair`) stays as the net for models that refuse the field, and the hub remembers those models. (b) **Symbols.** A fix plan names its places by a *symbol* (a class or method, a function, a component, a JSON key path, a Markdown heading, a CSS selector, or `imports`), and the hub finds the lines in the file it read. A name that is not there is refused with the nearest names, never with lines.

**Why.** Measured on 2026-11-23: the hub accepted 2 of 10 plans, and most refusals came from the form the hub asked for, not from the model's understanding: a line copied verbatim as an anchor (line numbers, lines that occur three times, lines remembered wrong) and JSON with code in its strings, repaired afterwards. Copying a line exactly is the hardest output for a 20-30B model; naming a function is easy. A grammar removes a whole class of repair code.
