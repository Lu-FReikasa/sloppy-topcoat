# D120 — The same failure twice stops the automatic drafts

> **Status (2026-11-25):** Built as step 1.13 of the plan of 2026-11-24 (`failure_print.py`, `issue_fixes.FixService.next_draft`). Tested on real failures; a stop has not been seen live yet.

**Decision.** When a fix fails, the hub takes a fingerprint of the failure: the error class, the first red test and the first error line, with numbers, ids and paths taken out. Two drafts in a row with the same fingerprint stop the automatic drafts of that issue, and the person gets an inbox item `fix_blocked`; the person decides how to go on. This complements [D84](D84.md): a review loop with new questions has no hard limit, a loop that repeats itself does.

**Why.** On 2026-11-23 three iterations of one issue failed the same way, and another got the same pytest output eleven times. The same context gives the same answer, so a failure that repeats is not worth another automatic draft; it is worth a look by the person.
