# D124 — The memory is simplified

> **Status (2026-11-25):** Decided by the maintainer. Being built (issue #28): the use counts are no ranking input any more, and the slots and cue words are gone (contradictions are the ones the model names, settled by `memory_auto_settle`). Not built yet: the removal of the care run's verification path. Amends [D19](D19.md), [D22](D22.md) and [D37](D37.md).

**Decision.** The memory keeps what made it trustworthy and drops the machinery that did not work.

- **Kept:** every note versioned with a reason and reversible; the secret filter on every write path; `user_id` scoping ([D20](D20.md)); the core block ([D38](D38.md)); a memory per program with the tag tree ([D74](D74.md)); explicit "remember this" ([D42](D42.md)); learned rules in a narrow frame ([D48](D48.md)); the expiry of volatile notes; the core only for notes about the person.
- **Dropped:** the slot and cue-word heuristics on the person's text ("tatsächlich", "umgezogen", single- and multi-valued slots); the verification path of the care run (`verify_with`, checks through the agent loop); the usefulness arithmetic (recalled and used counts, feedback weights) as a ranking input.
- **Contradictions** are settled by the hub from the evidence it has: the stronger evidence wins, then the latest statement of the person; contradicting assumptions are archived. Only when that does not decide is the person asked.
- **Measured before and after** with the same queries as the audit of 2026-11-21 (share of recalled notes that are used, duplicates, open contradictions, size of the core).

**Why.** The live audit of 2026-11-21 found 7-12 % of recalled notes used, duplicates and contradictions that survived the consolidation, project ephemera in the core, and a care run that checked nothing and only lowered trust; no usefulness feedback was ever given. The heuristics steer by words, which the plan of 2026-11-24 replaces elsewhere too. Less machinery that works beats more machinery that does not.
