# D125 — The chat sees images the person gives it

> **Status (2026-11-26):** Decided by the maintainer. The chat part is built (`chat_images.py`, issue #51; the projector on the node in #50); changing an image through the image service (D126) is not.

**Decision.** A person can give the chat images (paste, drop, file, a screenshot from the desktop client). The hub stores each image for that person only ([D20](D20.md)), re-encodes it (no metadata such as location) and keeps it within size limits; in incognito ([D63](D63.md)) it lives only in memory. The image is sent only to a **local** model that can see: the node loads such a model together with its projector file (`--mmproj` of `llama-server`), and the hub knows from the model facts which loaded models can see and routes an image there. A model that cannot see never gets the image and the chat says so. What the model reads in an image is data, never an instruction (like a web page). To **change** an image the chat hands it to the image service ([D126](D126.md)); the result comes back as a new image, the original stays.

**Why.** The maintainer wants to show the assistant screenshots, photos and designs and have it understand and edit them. Everything stays on the home machines, as the rest of Topcoat does (D33).
