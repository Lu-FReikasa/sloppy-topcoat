# D126 — Images are made locally by a second runner on a node

> **Status (2026-11-25):** Decided by the maintainer (plan of 2026-11-24, C5 and recommendation 15). Not built: milestone *P6 Images*.

**Decision.**

- **Runner.** A node manages `stable-diffusion.cpp` (its server) the way it manages `llama-server`: a pinned official release per platform and backend, verified by hash, bound to loopback, reached only through the node session. Only models that `stable-diffusion.cpp` can load (GGUF and its formats). No ComfyUI or other heavy stack (the node stays small).
- **Actions.** `image.generate` (prompt, size, seed, steps, style) and `image.edit` (an image plus an instruction: image-to-image or an edit model), named, schema-checked, whitelisted per node.
- **Image mode.** A node with little memory switches into image mode **only on request**: it unloads its text model, makes the images and loads the text model again. The person sees that the node is in image mode; chat work goes to other nodes meanwhile.
- **Results** are stored per person as hub files ([D114](D114.md)) with prompt, seed and model, so an image can be made again.
- **Pixel look without a pixel model.** A deterministic post-processing step (fixed palette, colour quantisation, nearest-neighbour downscale, outline) turns any generated image into pixel art, so the prompt stays free ("inspiration") and the look stays consistent. **Animations** are frame sequences assembled into sprite sheets (same seed and small changes, or image-to-image from the previous frame), shown by CSS steps.
- **Atelier.** A program to prompt, compare, edit and keep images; other programs (Development for themes and personas, the chat for edits) use the same actions.

**Why.** The maintainer wants local image generation and editing, generated assets for themes and personas, and free prompting as inspiration. One more runner under the node's existing rules (whitelist, loopback, pinned binaries) adds the ability without a new kind of door.
