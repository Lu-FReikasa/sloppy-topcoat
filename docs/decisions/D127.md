# D127 — Voice: a live conversation with an agent

> **Status (2026-11-25):** Decided by the maintainer (plan of 2026-11-24, C5 and recommendation 16; taken into the roadmap now, before the secretary; the goal "live, not prompt and answer" added the same day). Not built: milestone *P7 Voice*.

**Decision.** The goal is a **live conversation**: the person and the agent talk as people do, with short reaction times, the person can interrupt (barge-in), the agent can be interrupted and reacts at once, and it can still use its tools and knowledge. Push to talk with prompt and answer is only the first step and the fallback.

- **Two ways, measured before one is chosen.**
  1. *Streaming cascade:* voice activity detection, streaming speech to text, the text agent with its tools streaming its answer, streaming text to speech that starts with the first sentence, and barge-in that stops speech and the model's turn. Works with every local text model and keeps the agent's tools and rules.
  2. *A native full-duplex speech model* (first candidate: Haru-4B, which listens and speaks at once in 133 ms frames and speaks German; others to compare) as the voice in front, with the text agent behind it for tools and knowledge. Such models are base models without tools, so the coupling to the agent is part of the evaluation.

  The evaluation measures, on the maintainer's hardware, the time to the first sound, how interruption feels, German quality, memory and GPU needs, and whether the agent's tools stay usable. The maintainer chooses.
- **Where it runs.** Light services (whisper.cpp, Piper, voice activity detection) run as node services: pinned official releases verified by hash, loopback only, interfaces with fakes. Heavy runtimes (PyTorch, as a full-duplex model needs) never go into the node binary: they run as a **voice service in its own process or container that connects to the hub like a node** (a tool plug-in, [D105](D105.md)), on a machine with a suitable GPU. Not in the hub's own container ([D7](D07.md)).
- **Audio path.** The browser or the desktop client streams audio both ways over the person's TLS connection to the hub and through the node session to the service; no listening port anywhere.
- **A channel, not a program.** Voice is a way to talk to the assistant: first the chat of today, later the secretary ([D112](D112.md)), with "connect me with Administration" and back. Each persona can have its own voice.
- **No confirmation by voice.** A spoken "yes" never confirms an action; the voice names the card, the person confirms by click or key ([D15](D15.md), [D83](D83.md)).
- **Privacy.** Audio is not stored; the transcript is a normal message of the conversation; in incognito nothing is written. A voice reference clip for a persona is an asset of that persona ([D114](D114.md)).

**Why.** The maintainer wants to talk with an agent live, not wait between a prompt and an answer. A cascade keeps the agent's abilities, a full-duplex model feels most natural; which balance works on home hardware has to be measured. Keeping heavy runtimes out of the node binary keeps the node small, and connecting them like a node keeps every rule of the baseline.
