# D16 — Nodes give GPU memory back on their own when other programs need it

**Decision.** Nodes give GPU memory back **on their own** when other programs need it — generic signals, no list of programs needed: free VRAM below a threshold; the driver demoting our model memory to system RAM; or *unmet demand* — another program placed in system memory (shared GPU memory) while free VRAM could not hold it — and reload the models the hub lists as **residents** once the GPU has been free for a while. Process rules stay as the immediate fast path and veto reloads while they match. A manual unload in the GUI clears the model's `auto_reload`; a flap guard pauses models that keep being pushed out. This supersedes "the watcher reloads nothing automatically" (E1-06)

**Why.** Nobody can list every game, 3D tool or AI app; on Windows/WDDM a game rarely fails an allocation but pages our buffers out, which slows both, so the node must notice demotion. Test 1 showed WDDM may also leave our memory alone and put the **other** program into shared memory (LM Studio next to our 7B model), hence the third signal. Bringing residents back keeps the LLM available without manual steps. These are fixed, user-configured rules on the node, not AI actions, so D15 does not apply.
