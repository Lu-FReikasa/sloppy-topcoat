# D17 — The Windows service runs as a virtual account

**Decision.** The Windows service runs as the virtual account `NT SERVICE\topcoat-node` instead of LocalSystem. `install` adds that account (by SID) to the builtin group "Performance Monitor Users" (`S-1-5-32-558`, needed for the GPU counters) and gives it, SYSTEM and Administrators the data dir; `uninstall` removes both again. Process image paths come from `NtQuerySystemInformation(SystemProcessIdInformation)` and process sessions from `SystemProcessInformation`, which need no process handle (package `winproc`; `OpenProcess`/`ProcessIdToSessionId` are refused for the user's processes, found with the input helper).

**Why.** Least privilege: the node downloads binaries and runs model servers, so a compromised node should not own the machine. Test 1 (A7) showed the two gaps of a virtual account — GPU counters (fixed by the group) and other users' process paths for `path_prefix` rules (fixed by the handle-free query) — and nothing else.
