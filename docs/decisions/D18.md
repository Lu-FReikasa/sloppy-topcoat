# D18 — Model gateway

**Decision.** Gateway (E1-05): clients authenticate with **per-user API keys** (random `tc_…`, stored as SHA-256 with `user_id`, created and revoked in the GUI; the dev admin token also works until OIDC). The catalogue key is the **model name as the node reports it** (file name without `.gguf`); `model@node` pins a node, no cross-node aliases yet. The gateway **loads on demand but never unloads** another model to make room. Concurrency: ~~at most `TOPCOAT_GATEWAY_MAX_STREAMS_PER_NODE` (default 8) streams per node, more wait for a slot; queueing per model/slot is left to `llama-server`~~ **replaced on 2026-10-31 by D94: the queue of a node is as large as the node reports (`n_parallel`), the order is decided in the hub.**

**Why.** Editor plugins, chat apps and scripts all speak "OpenAI with a bearer key"; per-user keys keep D8 (user_id on every row) and can be revoked singly. Names stay what the user sees in the GUI; aliases need a model identity (hash) first. Evicting models is a policy decision (whose model wins?) that belongs to stage 2 with the scheduler.
