# D19 — The assistant keeps its own memory

> **Status (2026-11-25):** Under review. The principles hold (versioned, secret filter, reversible, per person). The self-maintenance does not deliver: the live audit of 2026-11-21 found 7-12 % of recalled notes used, duplicates and contradictions that survived the consolidation, and a care run that checked nothing. Simplify before adding more.

**Decision.** The assistant keeps its **own memory** and may write, merge and correct it **without per-item confirmation**. Every memory item carries user, source (chat/tool/web/doc + reference), time, confidence and an evidence tag (`[live]` / `[doc]` / `[assumption]`). An **idle consolidation job** (runs only when a GPU node is free and no game/pressure is active) merges duplicates, flags contradictions and corrects outdated items. Nothing is deleted silently: every change creates a new version with a reason, the history stays, and the user can inspect and revert any change in the GUI. A secret filter blocks credentials, keys and tokens from ever being stored. **The memory maintains itself (extension, E2-02 fix F):** when notes contradict each other — noticed in a conversation or in a tidy-up run — the agent clarifies and corrects them on its own, traceably (new version with reason and *source*: the conversation, the user's cue, the evidence) and reversibly (undo). It gathers evidence with a time per note (what the user said and when, corrections, repetitions; later the knowledge base, the web and tools as further evidence sources) and settles a contradiction only when the evidence is clear: an explicit statement of the user counts as certain ("ich wohne *tatsächlich* in …", "das war nur ein Test"), a merely newer statement of a personal fact does not. When it cannot establish the truth — no verifiable fact, or the sources contradict — it asks the user a formulated clarification question in the GUI. The user normally need not edit the memory; the memory page stays as the override.

**Why.** Memory is the assistant's notebook, not a system: writing it changes no machine, so D15 (confirmation for state-changing actions) does not apply — but only to memory. Versioning and a visible change log keep it trustworthy; the secret filter keeps it safe to show and to search.
