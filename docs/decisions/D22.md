# D22 — Memory notes

> **Status (2026-11-25):** Amended by [D124](D124.md) (the maintainer, 2026-11-25): store, versions, secret filter and scoping stay; the slot and cue-word heuristics go, contradictions are settled by evidence or asked.

**Decision.** **Memory (E2-02, implements D19 and D20).** Notes live in `memory_items` (text, vector, `evidence` `live`/`doc`/`assumption`, confidence, status `active`/`disputed`/`superseded`/`deleted`, source reference, version) with a `memory_versions` row for **every** change (text, status, evidence, reason, actor `chat`/`consolidation`/`user`); reached only through `MemoryStore(db, user_id)`, which scopes every statement — vector search, keyword search and the pair search of the consolidation included — by the user. **Writing:** after a completed answer a small model call (the conversation's model) proposes notes as JSON; each goes through the secret filter (deterministic patterns: passwords, keys, tokens, PEM, credentials in URLs, IBAN with mod-97, card numbers with Luhn, long mixed tokens; plus the model's own `secret` flag) — a refused note is never stored, only the *rule name* is logged and counted in `memory_blocks` — then everything is stored directly — except what the user did not say: a candidate that the user's own message does not state (its values — city, name, number — are not in the *statements* of the message; questions state nothing) and that only repeats what notes already say is dropped (an echo of the prompt: "Was weißt du über mich?" adds and confirms nothing). An identical or near-identical (cosine ≥ the embedder's `dup_threshold`, and no value the old note lacks) note that the user did state **confirms** the existing one: `confirmed_count` and `last_confirmed_at` are updated — no new version, no `updated_at` (nothing changed, and the consolidation is not woken up) — and never both notes of a dispute in one go. Chat-derived notes are `[doc]` (the user said it) or `[assumption]` (the model inferred it); `[live]` is reserved for facts a tool verified (E2-04). The chat shows "remembered: …" with undo (soft delete) and the model's `memory_refs` (a snapshot of the notes it saw) stay with the answer. **Recall:** vector and keyword hits (rank-fused, at most 6 notes / 400 tokens) enter the system prompt with their tag; the prompt tells the model that the user's latest message wins over a note and that memory is only what is listed. **Contradictions and self-correction (D19 extended):** the extraction call also receives the notes the answer was given (numbered) and may name, per new note, the ones it contradicts (`contradicts`) and, at top level, notes the user called wrong (`retract`). The model only proposes; the hub decides (`memory_clarify.py`, pure logic, no I/O): (1) **Slots** — notes about the same thing (residence, birthday, age, name: *single-valued*; work, pets, family: *multi-valued*) are candidates for a contradiction by their kind, not by vector similarity (the hashing embedder finds no likeness between "Musterstadt" and "Hamburg"); two notes of a single-valued slot with values that exclude each other (neither value set contains the other, so a refinement like "… an der Elbe" is no conflict) clash whatever the model said. (2) **Cues in the user's own statements** (questions state nothing): correction words ("tatsächlich", "nicht mehr", "inzwischen", "jetzt", "umgezogen" …) make the new note *replace* the clashing ones (`superseded`), words that call earlier statements a test or wrong ("waren zum Testen", "war falsch") *withdraw* them (`deleted`, restorable) — without asking, because an explicit statement counts as certain; the chat shows "Corrected: … (replaces: …)" / "Withdrawn: …" with **Undo** (`POST /api/memory/{id}/undo` deletes the correcting note and restores everything it replaced). (3) **No cue** (a plain newer statement): not decided — both notes become `disputed` (linked, the newer one suggested) and **one clarification question** is opened per group of notes in doubt. (4) **Judgement:** `judge()` looks at evidence with times collected by pluggable `EvidenceSource`s (today `ConversationEvidence`: the statement a note came from, whether it was a correction, every confirmation) and decides only when it is clear — a source names the winning note as *decisive*, or the newest note's statement corrected the others and nothing was said since, or the user said one note again after the others' last evidence; contradicting decisive evidence or a merely newer statement → ask. The knowledge base, web and tools (E2-03/E2-04) plug in as further evidence sources. Every verdict is applied with the evidence as the version's reason. (5) **Questions** (`memory_questions`, per user, D20): a formulated question with the candidate notes and their dates, answered in the GUI by choosing a note, "none of them" or free text (or put aside with "later": not asked again until something changed); the answer is applied like an explicit user statement (the chosen note is confirmed, the others become `superseded`; "none" withdraws all; a text becomes a new `[doc]` note, refused if it looks like a secret) with the question as the version's source. Open questions show as a badge in the navigation, a card at the top of the chat and on the memory page — never to another user. (6) **Honest certainty:** each prompt line carries the note's trust in plain words after a dash ("— the user said it, confirmed several times", "— only inferred, unsure", "— disputed: contradicts another note, not settled"; never a machine format like `[doc] (confirmed 5x)`, which a 7B copies into its answer), and the prompt says these remarks are for the model only, never to be quoted, and never to claim certainty about a disputed note; as a last line of defence a streaming `MarkerFilter` strips `[doc]`, `[live]`, `[assumption]`, `(confirmed Nx)` and `(disputed)` from the answer before it is shown or stored. For a follow-up like "Wie sicher bist du dir?" the notes the previous answer used are given again. (7) **No orphaned disputes:** `heal()` runs wherever notes change (conversation, answer to a question, undo, revert, delete, resolve, edit) and as a safety net in every tidy-up: a `disputed` note none of whose opponents is still `disputed` (linked or clashing by slot) becomes `active` again with the reason "contradiction resolved: …", and a question with fewer than two live notes left is closed. (8) **Source messages are evidence:** `SourceMessageEvidence` reads, per note, the user's own message it came from (`source_ref` → the user message before the answer, of the note's own user); a correction or withdrawal in it (the same cues) is a *correction* with the quote as the reason — so notes written before the cue logic existed settle deterministically in the tidy-up. If that is not clear the model is shown those messages (`CLARIFY_SYSTEM`) before any question is asked; it may name a winner only with a quote that is verbatim in the winner's message and only if the winner has the last word (newest evidence); anything else stays a question. A doubt the model already read in an unchanged state (same notes, texts, confirmations) is not put to it again (`model_checked` on the question). Near-duplicates merge on write only if the new note adds no value the old one lacks. For a message about the user ("ich", "mein", "über mich") the most important notes (surest evidence, confidence, newest) fill the recall budget after the notes the search found. **Consolidation:** an idle job per user (scheduler tick every `TOPCOAT_MEMORY_CONSOLIDATION_INTERVAL_SECONDS`, and a manual "tidy up" run) starts only when a node is `available` (no game, no VRAM pressure) and — for scheduled runs, only if `TOPCOAT_MEMORY_IDLE_SECONDS` is above 0 (default 0: the node's queue serves chat first) — no chat answer ran for that long; it works on one user's notes at a time in batches (clusters of similar notes first), first (no model, no tokens) looks again at every group of contradicting notes — also the ones already `disputed`, with everything known now — and settles or keeps asking (stats `resolved`, `questions`; a disputed note whose rival is gone is active again), then asks the model for `merge` / `conflict` / `correct`, validates the plan (unknown numbers, notes already handled, texts the secret filter refuses are ignored) — and **a merge must never lose a fact**: a merge whose reason speaks of a contradiction, or whose result would lack a value of any merged note, becomes a conflict (so does a correction that copies a fact of another note), and a kept note is only reworded when the dropped notes add something to it — and applies it: merged duplicates become `superseded`, contradictions become `disputed` (both kept, linked, the user decides on the memory page), corrections are new versions with the model's reason; a run stops at its token or time budget. Nothing is deleted silently; the user can revert to any version, restore deleted notes, and "forget everything" is a soft delete (permanent removal is a separate, confirmed action). **Embeddings:** behind `Embedder`; until an embedding model is served through `/v1/embeddings` (E2-03, bge-m3) the **transitional `HashingEmbedder`** is used — words and character trigrams hashed into 384 dimensions, no model needed, matches shared words and word stems rather than meaning, marked as transitional in the log and on the memory page. Every vector records its embedder; setting `TOPCOAT_EMBEDDING_MODEL` switches to `GatewayEmbedder` and the next consolidation re-embeds the old notes.

**Why.** Memory is the assistant's notebook, not a system (D19): it may change without per-item confirmation but never silently, and never across users (D20). Storing everything with a version and reason makes every automatic decision inspectable and reversible; the secret filter runs before storage because a note that is never written can never leak. The hashing embedder keeps the feature usable today without a model download and without a second code path later.
