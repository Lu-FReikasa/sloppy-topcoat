# D25 — A durable, per-user queue for deep tasks

> **Status (2026-11-25):** Replaced. The table `deep_tasks` no longer exists; background work runs as agent tasks through the hub's queue ([D86](D86.md), [D94](D94.md)) and as block programs ([D115](D115.md)).

**Decision.** **A durable, per-user queue for deep tasks** in the hub (`deep_tasks`): survives restarts, `user_id` on every row and every query (D20), a priority, a `kind` (`memory_extract`, `memory_consolidate`, `verify_answer`, later research), a JSON payload, a `step` counter for multi-step tasks, and a status `waiting` / `running` / `paused` / `done` / `failed`. A worker picks the next task by priority and age, chooses a node through D23 and runs it through the gateway; a paused or unloaded node sets the task `paused` and it continues at its current step when a deep node is free again; with no deep node available the task waits or — by a configurable rule — falls back to a `fast` node when the task allows it. The GUI shows the queue of the signed-in user only.

**Why.** Thorough work is slow and its machine comes and goes; without a durable queue the work is lost with every restart or pause, and without `user_id` scoping the queue would leak one user's notes into another's prompts.
