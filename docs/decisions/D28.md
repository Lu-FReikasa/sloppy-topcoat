# D28 — Energy

> **Status (2026-11-25):** Note. Waking a node on demand (the last sentence) is planned as step 1.7 of the plan of 2026-11-24.

**Decision.** **Energy: a node costs little while it waits, and can be woken.** (a) `config.power.profile` (`performance` / `balanced` / `saver`): while a node has nothing to do — nothing loaded or loading, no resident to reload, not paused — it looks at the hardware less often (pressure and yield polls ×3 / ×6, the GPU not at all) and in `saver` reports less often. (b) The inventory lists the physical network interfaces; the hub keeps them, so it can send a **Wake-on-LAN** packet to a node that is asleep or off (`POST /api/nodes/{id}/wake`). (c) A node can be put to sleep by an admin (`node.sleep`, not a default permission) or, if configured, by itself after `sleep_after_idle_seconds` without work, resident, or user. Waking on demand by the gateway is a later step.

**Why.** The fast machine is only switched on when it is needed; the laptop should not burn watts polling an empty GPU. Sleeping is explicit because coming back depends on BIOS/NIC settings the software cannot check.
