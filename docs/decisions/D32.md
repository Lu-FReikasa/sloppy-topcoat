# D32 — Connectors

**Decision.** **Connectors: the assistant reads other systems through a tool node, with credentials that exist only in a file on that node (E2-04c).** Uptime Kuma (its Prometheus `/metrics`, API key) and the Omada controller (Open API, client credentials with the role Viewer) are read-only capabilities like the Docker ones (D29: grants per user and node, audit, limits, masking) — the new thing is the credential path: a file the maintainer creates on the tool node (mode 600, owner checked, no link), read only by the node, **never** in the hub's configuration, an input, an output or the audit; redirects are not followed; a capability is offered only if its section exists. The pattern for OPNsense, Proxmox and Unraid is the same: a section in the file, one client, a few filter-only capabilities.

**Why.** The hub must not hold the keys to the network: a hub database dump or a prompt injection then reaches the same read-only facts the tool already shows and no credential. Viewer roles and read-only endpoints keep a bug in a connector from changing anything; the file on the node is the one secret the maintainer manages.
