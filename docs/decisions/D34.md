# D34 — The knowledge base reads notes through a tool node

> **Status (2026-11-25):** Amended. The Outline sources are gone ([D107](D107.md)); released reports, projects and Akten are knowledge sources ([D102](D102.md)). The exclude list nobody can shorten holds.

**Decision.** **The knowledge base reads notes through a tool node, with an exclude list nobody can shorten (E2-03 slim).** Folders of Markdown/text are indexed by the hub via two read-only capabilities of a tool node (`docs.list`, `docs.read`: released roots only, default deny, no links, no path outside, pages of 24 KiB, masked like every tool output). A path with a segment matching the fixed exclude list (`*SENSIBEL*`, `*ZUGANGSDATEN*`, key/env/password/secret names …) is not listed, not read and not named by the node, is never asked for or indexed by the hub, and a hit whose path matches is dropped even if the list grew later; `docs_exclude` / `TOPCOAT_KNOWLEDGE_EXCLUDE` only add. The D19 secret filter runs on every chunk: a chunk with a password, key or token is not indexed, the GUI lists the files and rule names, never content. Sources are admin-created, `shared` (everybody searches) or `private` (owner); files and chunks carry `user_id`, every query is scoped by what the caller may see (D20), where the files lie is the owner's knowledge. Search is hybrid (Postgres full-text without stop words + pgvector cosine, rank-fused); chunks are stored without a vector while no embedding model answers and filled in by a later run, the transitional hashing embedder is used (and labelled) until `TOPCOAT_EMBEDDING_MODEL` is set. The agent gets `knowledge.search` as a pseudo tool next to the machines' capabilities (never alone); its hits are `[doc]` evidence — documents that may be out of date, never proof of the machine's state — and go through the escalation's redaction like any evidence (D33). **Directory first (E3-04):** a generated `10_KI_Verzeichnis.md` maps hosts and services to sections of the notes (with lines); a host or service named in the question is looked up there before the similarity search and exactly those sections are returned (never whole files, never a path the node did not list, each through the secret filter), tagged with the age of the directory; the similarity search fills what is left. A note that disagrees with a live result is reported as such (`contradicts` on a `live` finding that cites both) with the advice to update the note — the assistant never edits notes. The embedder becomes bge-m3 by itself as soon as a node serves it.

**Why.** The maintainer's notes are the context a small model lacks, but they sit next to credential files: a rule on *names* that is enforced at both ends and cannot be configured away is the only thing that holds when a folder is released in a hurry, and a secret filter on content catches what the names miss. Reading through a node keeps the hub without file access to the LAN and reuses D29's allow-lists, masking and audit. A directory turns "which of 2000 passages look similar" into "which sections the maintainer says are about this host": few, exact and quotable with their lines; the directory is only a pointer, so everything it names still passes the same exclude list, listing and secret filter.
