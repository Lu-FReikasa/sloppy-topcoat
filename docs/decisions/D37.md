# D37 — The assistant tends its own memory

> **Status (2026-11-25):** Under review. The audit of 2026-11-21 found that the care run checks nothing (all "not verifiable") and only lowers trust, and that no usefulness feedback was ever given. The expiry of volatile notes holds; the verification path and the usefulness arithmetic need a new look.

**Decision.** **The assistant tends its own memory: reliability and usefulness are separate, and age alone never deletes (E3-05, builds on D19/D22).** A note has a **kind** (`person`, `preference`, `operational` = about the user's infrastructure) and, only when it is a volatile state ("service X is down"), an `expires_at` (default 24 h; the care run soft-deletes it afterwards, with the reason). **Reliability** = `base x trust x 0.5^(age / halflife)`: `base` by evidence (`[live]` .95 > `[doc]` .8 > `[assumption]` .5), the age runs from the last confirmation or check, the half-life belongs to the kind (person 365 d, preference 180 d, operational 14 d, volatile 1 d; all `TOPCOAT_MEMORY_*`) and grows with every confirmation (x1.5 each, at most x8) — a live check counts double a statement, a dispute multiplies by 0.3, an explicit correction by the user is a fresh note. **Usefulness** is a different number: `recalled_count`, `used_count`, `last_used_at`, feedback; it is the smoothed share `(used + 2) / (recalled + 4)` (no data = neutral) softened by the recency of the last use, the user's feedback ("helped" / "did not fit") weighing three times. A note counts as *used* only when **two signals agree**: the model names it (measured in the extraction call that already reads each exchange, `used: [numbers]`, so nothing is added to the answer text) and the answer shares its terms; with no model signal only a very high overlap counts. **Rules.** Recall ranks relevance x reliability x usefulness; the model sees **stages only** (sure / older, not confirmed again / outdated, please check), never numbers; a note is **archived** (status `archived`: soft, searchable, restorable, a version records it) only if usefulness is low **and** reliability is low **and** it has not been used for long — an old note that is often used is only checked; a person or preference note that is outdated is asked about at most once per conversation, in passing, and only if the search found it for the current message. **The care run** (`memory_care_service`, once a night at `TOPCOAT_MEMORY_CARE_HOUR` and after idle, preferring the deep role = the model of the `thorough` level; per user, one at a time) first strikes expired notes and archives the unneeded ones, then checks the notes below the check threshold that carry a `verify_with` (a read-only capability and its input) through the agent loop, origin `care` (hidden from the task list). The task gets **only the tool group of that one capability** — never `notes` (nothing the knowledge directory excludes can be reached) and never the internet — and a short second model call judges the evidence: *confirmed* (`last_verified_at`, counted twice as strong), *changed* (a new version with the evidence refs, `[live]`), *not verifiable* (trust x 0.7, not below 0.2) — a verdict must cite evidence of that very check. A note the user said (`[doc]`) that a live check contradicts is **never overwritten**: it is marked disputed and a clarification question (D22) with what the check saw is opened. A busy or game-occupied node pauses the run (`paused`), the budget (notes, seconds) stops it (`stopped_budget`); person and preference notes without a check are left to the consolidation and the chat. Every change is a version (`actor = care`) with its reason, and the run's report lists each with what undoes it. The agent stays read-only (D15): no care step changes anything on a server.

**Why.** A memory that only grows becomes wrong silently, and one that forgets by age loses exactly the facts nobody re-states (a person's birthday). Separating *can I trust it* from *did it ever help* lets the assistant verify what is stale and shelve only what is both doubtful and useless; asking the model to report its own use inside the answer would have cost small models their answers, so use is read from the call that is made anyway.
