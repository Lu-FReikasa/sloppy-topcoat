# D40 — Times in the chat

**Decision.** **Times in the chat (E3-07 D2).** The database keeps every moment as `timestamptz` (UTC); the API always sends UTC ISO text (`api.chat._iso` converts, whatever time zone the database session has). Showing it is the browser's job, in the time zone of the browser's system: every message carries its time (`HH:MM`, 12/24 hours as the language decides) with the full date, time and zone as hover text; a line with the day (*Heute*, *Gestern*, else the full date) stands before the first message of every calendar day. A message that only exists in the browser so far carries the browser's own time of sending. A time that is missing or unreadable is left out, never invented.

**Why.** Users compare answers with their own day ("was that this morning?"); a server-side zone would show the hub's clock, not theirs, and a second device in another zone would disagree. UTC on the wire keeps the data comparable and the conversion in one place.
