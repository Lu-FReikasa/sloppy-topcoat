# D41 — Message kinds

**Decision.** **Message kinds: say, progress, report (E3-07 D3).** A conversation is made of messages of three kinds (`messages.kind`): a bubble (`say`), the line that shows which tool runs (`progress`, exists only while the check runs) and a report card (`report`, structure in `messages.report` JSONB, Markdown in `content`). A request that needs a finding is a *confirmation bubble* the hub writes itself, the progress line, the *card* that `report.build` makes from the agent task's diagnosis and evidence (no model call), and a *closing bubble* of at most two sentences from the model (`chat.closing_text` cuts what it writes). The card keeps findings (tag live / doc / web, evidence marks that the GUI links to the excerpts) and assumptions apart, and gives a proposal with impact and way back — the agent's `finish` now has `impact` and `rollback`; what it did not say is shown as *not stated*, never filled in. The run (D39) stays one run: it is registered under the ids of all its messages (`AnswerRuns.alias`), so a reload attaches whichever message it sees *running*; the confirmation is written into the message the run started with, the progress line, the card and the closing bubble get messages of their own. For the prompt, progress lines are skipped, the card is given as text (`[Report card …]`) and the assistant messages of one question become one turn (templates want alternating roles).

**Why.** The model used to write the whole report itself, in a free-flowing bubble: findings and guesses mixed, evidence marks it could get wrong, and the same content a second time in the next sentence. Building the card in code makes the report *checkable* (every mark leads to the excerpt it names), keeps what is known apart from what is assumed, and leaves the model the one thing it is good at — saying in a sentence what matters. A progress line that disappears at the result shows that something is happening without cluttering the history.
