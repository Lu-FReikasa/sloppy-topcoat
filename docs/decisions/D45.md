# D45 — The inventory

**Decision.** **The inventory: what runs on which node, kept with its age (E3-10).** A tool node answers one read-only capability, `inventory.snapshot`: host facts, every Docker container and the systemd services that are active, failed or enabled, as **three sections that each say on their own whether they could be read** (`ok`, or `code`/`error`). The hub reads every connected node that offers it on a timer (`TOPCOAT_INVENTORY_INTERVAL_SECONDS`, default 300 s; also on demand) through the normal capability path — the node's config must switch it on, it must be read-only, the input is checked — as the system user, and keeps per node when it looked, how each section fared and its last good read time, plus one row per container/service (`inventory_items`, with *since when the hub has seen this state*). Reliability rules: (1) a section that **failed changes nothing** — items are marked gone only when a successful look for that section no longer lists them and the list was not cut short, so a Docker daemon that did not answer never becomes "no containers"; (2) every answer carries its age: a look older than three intervals is *stale*, a node that is not connected is *offline*, and both are shown as *last known*, never as current; (3) compose projects are derived from the containers of the same look, not from a second source. People see a node's inventory only with the right to run `inventory.snapshot` on it (D20: admin on the GUI, else a grant, never an API key by inheritance); the chat and the agent read it through a hub-side tool `inventory.list` that **asks no node** and returns, next to the rows, the nodes that are offline/stale and the sources that could not be read, so the model can say how much to trust it. The periodic read leaves no audit row when it works (one per node per interval would drown the log); a refused or failed one is audited like any call. Read-only end to end; the inventory is not evidence for a proposal (D43 still wants a live listing).

**Why.** The assistant's first goal is to know the home lab ("where does Plex run?") before it gets more tools. A stored look is only useful if it cannot lie: a failed read must look like a failed read, and an old look like an old look.
