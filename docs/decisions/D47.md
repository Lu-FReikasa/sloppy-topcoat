# D47 — The identity view

**Decision.** **The identity view: who may use which app, read from Keycloak, never written (E3-12).** A tool node with a `keycloak` connectors section answers `keycloak.snapshot` (three sections that each say whether they could be read) and `keycloak.user`; the credentials are a service account with read roles only and live in the connectors file. The hub builds the chain *person → group (with parent inheritance) → client role → app* from the snapshot (`identity.py`), keeps it in memory for a minute (never stored; every call re-checks the right to run the capability) and shows it on the page *Identitäten* and as the chat tool `identity.query`. What the look cannot see is part of every answer: composite roles are not expanded, direct role mappings are not read, and an app that reads group claims appears only where the admin noted the groups by hand (hub setting `identity_app_groups`, marked "configured by hand"). Nothing is written to Keycloak or any app in this step; access grants are a later step and would go through D15.
