# D52 — The dev workshop

> **Status (2026-11-25):** Amended by [D76](D76.md), [D99](D99.md), [D103](D103.md) and [D108](D108.md).

**Decision.** **The dev workshop: the assistant works on code in a sealed place, the person decides what leaves it (E6-01, proposed; the maintainer agreed to the direction on 2026-10-09).** A *workshop node* (`--role dev`, a container on a server, no access to the hub database, hub.env, other nodes or signing keys) holds clones of **registered repositories** and offers the model only named, schema-validated actions: `repo.read`, `repo.search`, `repo.diff`, `repo.apply_patch` (inside the workshop's own worktree only), `repo.test` (a command chosen from the repository's *test template*, e.g. `make check`, `npm test`, `go test ./...`, `pytest`; never free text), `build.node` and `build.hub_image` (unsigned artefacts). No shell. Every test or build runs in a fresh throw-away container without hub data and without tokens, with network only to the repository host and the package source, with time and memory limits; this holds for foreign repositories, whose code is untrusted. A repository is a row (`dev_repos`, per user, D8): URL, default branch, mode `read` or `test-branch`, test template, a token reference; the token is stored encrypted and is never returned to a browser or written into a conversation. **What this changes and what it does not.** The worktree of the workshop is scratch (disposable, not a state of the lab), so patching it needs no click; it is shown as a diff. Such capabilities carry the inventory flag `scratch` (never together with `read_only`); the hub offers them to an admin only. *Committing and pushing* is a state change outside the workshop and follows D15/D43: a proposal card with the full diff and a secret scan, one click per push, only to a branch `topcoat/*` in a test repository or fork whose token cannot touch the default branch of the real repository; refused for every API key. The assistant never merges, never touches a default branch, never signs and never uploads to the update channel (D50): signing and rollout stay with the maintainer. Text from a repository (code, comments, PR texts) is data, never instructions (as in `github.read`). Every call, refused ones too, is audited. This supersedes the rule "the assistant's self-tool is read-only" for the workshop node only; the hub, the lab nodes and the tool nodes stay read-only.

**Why.** The maintainer wants to discuss changes in the chat and have the assistant try them, and to use the same place for other repositories. The risk is not the tool but a wrong or injected instruction: therefore the place is sealed, the verbs are named, and the only door out is a click.
