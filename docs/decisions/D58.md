# D58 — Parameters an admin changes while the hub runs

**Decision.** **Parameters an admin changes while the hub runs (E7-03).** Tuning limits, timeouts, thresholds and sampling used to mean editing ``hub.env`` and restarting. ``live_settings.py`` holds an allowlist (51 entries: the limits of a check, the coordinator, the gateway timeouts, chat sampling and effort, memory thresholds, the intervals of the inventory and the knowledge base, the flows) with type, bounds and group. A value is validated against the type of its ``Settings`` field and its bounds, stored in ``hub_settings`` (``live.<name>``), written into the running ``Settings`` object that the services hold (so what is read when it is used changes at once) and noted in ``setting_changes`` (who, when, from what to what; a reset is a change to null). What was copied into an object at start (the limits of the agent loop) is refreshed by a hook of its group. A preset (the changed values as one document) can be exported and put back, all or nothing. Secrets, paths and addresses are not on the list and cannot be reached through it.

**Why.** The allowlist, not a blanket editor, keeps a prompt-injected or mistaken request from reaching ``dev_admin_token`` or the database URL; the history makes every change readable and undoable.
