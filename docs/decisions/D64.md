# D64 — A node comes online

**Decision.** **A node comes online: what stopped for lack of it goes on (first trigger of docs/PLATFORM.md, section 4).** A task that ended because no tool node was reachable (``no_tools``, ``tools_missing``) stayed ended until somebody pressed "continue". When a node that was offline (or not seen since the hub started) comes online (``node_updated``), the hub continues those tasks: a few per person and arrival, only recent ones, only a limited number of times (``resume_stuck_*``), with the limits of the person's own continue; the inbox gets a note.

**Why.** A task bound to a node should not wait for a person to notice that the node is back; the limits keep one that keeps failing from looping.
