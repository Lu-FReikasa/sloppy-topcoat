# D65 — Hand-over between applications

> **Status (2026-11-25):** Under review. The planned secretary (plan 2026-11-24, E5, D112) hands reading tasks on without a click and reports results in the conversation; this text requires a click on the dossier and keeps results out of the sending conversation.

**Decision.** **Hand-over between applications (section 3.8 of docs/PLATFORM.md).** From a chat window (or an incognito tab) the person hands a request to another application: the agent writes a **dossier** (the request in full, a few quotes, what is asked, the form of the answer, what was kept back), the person reads it, and the click sends exactly it: the send carries the dossier's hash and is refused when it does not match the stored one (``handovers``, ``/api/handovers``). The other application works in a conversation of its own, started with its own tool scope; its memory and the sender's never mix. The answer comes back as a **summary in the inbox** marked with the application it comes from (``handover_result``; ``handover_failed`` is urgent); it is never written into the sending conversation, and a summary that holds private data (``redaction.private_kinds``) is replaced by a pointer to the application where the details stay. From an incognito tab only the question goes, without context.

**Why.** Separation must not rest on a model keeping quiet: the structure (own conversation, own scope, summary through a filter, hash-bound send) carries it, and the person sees what leaves before it leaves.
