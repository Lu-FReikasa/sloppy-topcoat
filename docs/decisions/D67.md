# D67 — The chat policy

> **Status (2026-11-25):** Replaced. The policy nodes went with the flows ([D59](D59.md)); the same keys are one setting document, `chat_policy` (`chat_policy.py`).

**Decision.** **The chat policy: policy nodes (sections 3.4 and 3.6 of docs/PLATFORM.md).** Five node types do not run, they state how the chat answers: ``policy_limits`` (turns, tool calls, seconds of a check), ``policy_second_look``, ``policy_recall``, ``policy_write_memory`` and ``policy_placement``. They have no edges and are left out of the reachability check. The chat reads them at the effort of the conversation (``chat_policy.py``) from the built-in "Chat answer" flow or from an admin's copy chosen with ``PUT /api/flows/{id}/chat-policy`` (``hub_settings.chat_policy_flow``); the built-in flow carries the numbers the hub used before, so nothing changes until somebody edits a copy. A policy that cannot be read (flow gone, invalid graph, database error) is the hub's own rule, never an error in an answer. The old code path of the chat answer stays: the policy decides *how*, the answer itself is not yet a flow.

**Why.** Tuning the limits, the second look, recall and notes needs no release, and one failure of the policy can never take the chat down. Moving the answer itself into a flow is a larger step that the policy makes safe to take later.
