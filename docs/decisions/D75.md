# D75 — The hub's own work as background flows

**Decision.** **The hub's own work as background flows.** Every background service (a chat ends: summary, check, learning, Nachlese; hand-over notes; tidying the memory; the care run with its steps; re-checking pinned answers; continuing stuck tasks; re-reading the knowledge base) has a built-in flow of a `trigger` node (when: rest, interval, night hour, event) and `step` nodes (on, model, limit), written at every start from the `TOPCOAT_*` settings (`background.py`). An admin duplicates one, changes it and chooses it for the work (`PUT /api/background/{task}/flow`); the services read the chosen copy through an in-memory registry, refreshed when a flow is saved and every minute; while the built-in flow is chosen the settings apply as they are. An interval of 0 in the settings still keeps a service from starting (the emergency brake), and a flow's interval is a minimum gap, the settings' interval how often the hub looks at all. Background flows are not run with a question (409); the editor lists their recent runs from the records each service already keeps.

**Why.** The maintainer wants the automatic work to be visible and set in one place, the node editor, and traceable — not hidden in environment variables.
