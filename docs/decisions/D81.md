# D81 — Applications talk to each other in typed messages

**Decision.** **Applications talk to each other in typed messages (PPH-05).** A message is `<sending application>.<purpose>` from a fixed registry (`proto/messages/registry.json`, one JSON Schema per type; an unknown type, an edge that is not listed or a payload that does not validate is refused). **Reading runs on its own, changing needs a click or a mandate:** requests, results, failures, clarifications and changelogs flow along the edges of the registry without a click, inside the grants of the project they belong to; anything that changes state outside the Project application is an *order* (D83). The applications know each other's *responsibilities* (a short text per application in the registry), not each other's contents: a message carries an opaque `chain_id` and `reply_to`, and the hub knows the project it belongs to.

**Why.** The person asks the Project application for an outcome, not for ten clicks. A fixed registry keeps free text from becoming a command, and responsibilities instead of contents keep one application from needing the context of another.
