# D85 — One table decides model and node

**Decision.** **One table decides model and node (replaces the configuration part of D78; not built, [SCHEDULING.md](../SCHEDULING.md) section 2).** One row per application plus the system rows `check` and `background`: priority, an ordered list of models, an ordered list of nodes, how long to wait for the first model. `same_as_answer` is a model of its own for the system rows. An empty row works: a fresh install with one model needs no configuration. What a person picks in a conversation wins. Removed: node default models, role lists, `app_roles`, `order`, `background_nodes`, `no_chat`, `no_background`, `quality_models`, `second_look_model`, `user_settings.default_model`, `handoff_slow_nodes`, the hub-wide default model, `auto` and every fallback to "any other model".

**Why.** The old answer to "which model?" had many layers, and work still escaped them: a summary ran as a chat request on the author's node and ignored `no_background`, and the fallback of the second look loaded a 26B model nobody configured. A model depends on the task and changes rarely; a node depends on the moment. `auto` treated size as quality and relied on measurements that were wrong.

**Built (2026-11-04), with these differences from the text above.** The table is stored in the policy (`applications`), read by the resolver and by the gateway, edited on the scheduling page (UI-02) and shown with a preview per row. The older lists are converted **once at start** (`legacy_policy.convert`, the result is written back) and are not read any more: `defaults`, `roles`, `app_roles`, `order`, `background_nodes`, `no_chat`, `no_background`, the node lists per task and the six environment variables are gone from the policy and from the API. A converted list keeps its meaning as far as a table can: the models and nodes of a list become the row (models and machines, no longer pairs: the best model first, on the first machine of the row that can take it); an order of nodes was a preference, so `all` follows it; nodes that were kept free are written out of the row. Work of no application (a script, the API without a tag) is the chat's; a request through `/v1` is the work of the row `api`. A row that says nothing leaves the choice to the hub's default model (not yet "the smallest model that fits"). `priority` moves the queue place of a row's requests by one (`gateway._place`); `wait_seconds` is stored and shown, **not yet used**. Not removed: `quality_models`, `second_look_model`, `user_settings.default_model`, `handoff_slow_nodes` and the hub-wide default model (other code reads them). See brief SCH-04-app-model-table.
