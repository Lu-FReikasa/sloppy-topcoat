# D86 — One queue in the hub, the node is chosen when there is room

**Decision.** **One queue in the hub, the node is chosen when there is room (built in part on 2026-10-31: the queue, the choosing function and the record, see D94 and D95; the lists per job come with the table, D85).** A job waits without a node; when a slot of a loaded model is free or a node can load the model, the hub gives it the most important job that node may and can run. Priority, then age, and waiting raises the priority. High and normal work may load and push a model out; low work and checks load only into free memory. Running work is never cancelled (decision of the maintainer, 2026-10-30). The queue is in memory. Every job leaves one row in a record: choice, source, reason, outcome, no content. The record replaces the planned `routing_decisions` table of OBS-01.

**Why.** Queues per node bind a request to a node too early, so one node can stay idle while another has a pile. Queues per kind of work would move the problem, because a node then has to choose a queue. One record also feeds the live view and the later questions, so there is one truth about what ran where. Cancelling would throw away finished work of long background runs.
