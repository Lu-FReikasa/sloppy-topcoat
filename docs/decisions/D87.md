# D87 — A check needs a fresh context, not a second node

**Decision.** **A check needs a fresh context, not a second node; chains order the work (changes the "other model" rule of the second look; built in part by SCH-02: a check may use the author's model and never loads one that pushes another out; chains not built, SCHEDULING sections 4 and 5).** A check may run on the author's model, and the review records whether it was the same model and node. A summary starts only after the check; if the check fails, is skipped or times out, the summary is stored as unchecked. If a second node has room, a check may start during the answer and take in tool results as they finish (`TOPCOAT_CHECK_PARALLEL`, off until measured).

**Why.** Every model request is complete in itself and a check already builds its own prompt from the database, so a clean context needs no extra machine. A second node adds speed; another model adds other mistakes; only the fresh context is essential. A summary written before the check could store false statements. Whether parallel preparation saves time depends on the prompt cache and cannot be tested without real machines.
