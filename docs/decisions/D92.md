# D92 — Model quality is rated continuously from the second look, with a floor as default

> **Status (2026-11-25):** Under review. Not built, and its main source (the model's follow-up check in the chat) is gone since 2026-11-14 ([D26](D26.md)). Shelve, or base it on the bench and the measured runs of plan step 1.19.

**Decision.** **The hub rates the quality of the models continuously and recommends models per application; until the table says otherwise a default floor applies (not built, QLT-01).**

1. **A running rating from the second look.** Every verdict of the second look (`chat_reviews`) and every checked statement of a summary (`chat_digests`) is folded into a rating per model, application and, where known, node: how many answers were checked, how many were confirmed, how many were corrected or contradicted, with the number of samples and the date. Tests passed and pushes accepted (PPH-05) count as the hardest signal and are kept apart.
2. **It recommends, it does not steer (D90 stays).** The rating is shown with its limits (a model that gets harder questions looks worse; few samples) and turns into a *recommendation* per application ("use `X` for Development: 18 of 20 bench tasks, 91 % of checked answers confirmed over 140 samples"). The person changes the table with one click. Speed may still decide the node on its own, quality never changes the model by itself.
3. **A floor as default.** A row of the table without a model, or with a model below the floor, falls back to a **minimum requirement or recommendation** per application: enough context, tool calling that works, a minimum size or a measured pass rate on the bench. The floor is data (a setting per application), is shown on the page, and is only a fallback: a chosen row wins.
4. **Comparable numbers still come from the bench** (`scripts/dev/topcoat_eval.py`, deterministic scoring, no model as judge). The running rating tells how a model behaves in daily use, the bench tells how it compares.

**Why.** The maintainer wants an ongoing, visible judgement of answer quality, built where checking already happens (the second look), and a sensible default for someone who has not chosen yet. D90 rightly refuses to let uncomparable signals steer; this keeps that and adds the feedback loop and the recommendation. Decided by the maintainer on 2026-10-31.
