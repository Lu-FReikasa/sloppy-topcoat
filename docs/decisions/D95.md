# D95 — The record of model requests holds no content and nothing of incognito work

**Decision.** **Every model request the gateway serves or refuses leaves one row in `job_records` (SCH-03 step 3, built 2026-10-31): when it arrived, started and ended, the work label, the chain of calling functions, requested and chosen model and node, the place in the queue, whether the model was already loaded, the outcome (`done`, `failed`, `cancelled`) with an error code, waiting and running time. The person, conversation, task and application are filled when the caller said so (`set_job_context`); a caller that did not leaves them empty. Never a prompt, an answer or a title. A failed write is logged and swallowed. Work labelled `incognito` is not recorded at all.** Who may read the table is D91.

**Why.** The numbers answer what the queue work is for: how long requests wait per node, which work waits, where models are loaded. A row that says who asked and when would be a trace of an incognito conversation, which the platform promises is never written (PLATFORM.md 3.9); `test_incognito` found that the first version wrote one. An answer must never fail because its record could not be stored.
