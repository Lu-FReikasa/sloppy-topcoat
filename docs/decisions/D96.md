# D96 — A tool description reaches the model whole where it is the only teacher

> **Status (2026-11-25):** Note. [D101](D101.md) keeps the descriptions of Research's answer tools whole as well; the contracts ([D118](D118.md)) describe the tools of an application in sentences.

**Decision.** **The description of a tool is cut when it is put into the model's tool list (`agent_prompts.native_tools`): to 400 characters in general, to 1800 for the tools of the project agent (`project.*`).** The rule is by capability prefix, so a new project tool needs no entry.

**Why.** The cut hid the operation names, their keys, the examples and "`node`, not `node_id`" of `project.changeset.propose` (1233 characters) from the model, and the schema of `operations` lists no keys, so the model learned the right form only from the error of a failed first call. That was the cause of "the first call often lacks `op`" (AGT-02). Measured with the hub's own schemas (`changeset_bench.py`): `gpt-oss-20b` 7 of 12 cases with the cut, 11 of 12 whole, 12 of 12 with the line on `project.node.create`; `Qwen3.5-9B` 8, 8, 10; `gemma-4-12B` stays at 8. The cost is about 240 tokens more in the core set of the project tools. Other tools stay short: a long list of tools of the other nodes would eat the context.
