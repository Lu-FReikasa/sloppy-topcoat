# D97 — Thinking is a setting per model family and quality level, and an everyday answer does not think

> **Status (2026-11-25):** Amended (plan step 1.8). The thinking parameters per model family are set in one place (`model_profiles.thinking`) for every call, agents included. gpt-oss gets `reasoning_effort` (`low`, `medium` when it should think) and a reserve of output tokens.

**Decision.** **Which request parameters a model gets for the quality levels `fast`, `balanced` and `thorough` is the live parameter `chat_effort` (per family of the model name; it existed since E7-03 and was empty). Set on 2026-10-31: for `gemma` and `qwen3.5` the levels `fast` and `balanced` send `chat_template_kwargs.enable_thinking = false`, `thorough` sends nothing and thinks. It applies to chat answers; the agent's own calls (`GatewayModel.complete`) and the checks do not send it yet.** Reset: `DELETE /api/admin/params/chat_effort`; every change is in `setting_changes`.

**Why.** Measured through `/v1` with six everyday questions: `gemma-4-12B` thinks 700 to 1200 hidden tokens even for a one-line translation (4854 tokens, 82 s for the six questions, one empty answer when the budget ran out); with the switch 1139 tokens, 17 s, no empty answer. `Qwen3.5-9B`: 7200 tokens and 5 empty answers against 831 tokens and none. `reasoning_effort: low` does nothing for gemma. Live: the first token of the same chat question came after 2.8 s instead of 14.4 s. The quality of the shorter answers was read by hand, not scored; a person who wants the long thought picks `thorough`. Open: the same for the agent's calls (the agent run with `gemma` ran into its time limit on 2026-10-31, the first model turn alone took about three minutes; the bench gave the same quality without thinking: 8 of 12 cases, 10 of 10 valid calls).
